## A. 가짜 자료로 한 번에 확인

### 준비는 한 번만

기존 [로컬 설치](../../frontend/README.md)를 사용한다. 실제 자료와 혼동되지 않는
가짜 소스만 사용하고, 기존 실제 소스의 설정/기기 UUID를 바꾸지 않는다.
앱 DB는 `l04d9e81c620`까지 업그레이드되어야 한다. 새 스키마 변경은 없다.
필요하다면 저장소 루트에서 아래를 실행한다.

```bash
.venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:app --reload
```

다른 터미널에서 `cd frontend` 후 `npm run dev`. 로그인하고
<http://localhost:5173/sources>를 연다. AI 권한은 끈 상태로 둔다.

- GitHub: 이미 등록한 `example/repo`, 저장소 ID123, `main`의 동일 선택을 재사용한다.
  없을 때만 등록한다. 카드의 **subscription ID**를 아래 명령에 넣는다.
  ID123이 다른 실제 설정으로 등록되어 있으면 덮어쓰지 말고 분리된 데모 환경을 쓴다.
- Codex: 가짜 새 기기 UUID와 `/synthetic/project`를 선택해 등록한다. 실제 Mac의
  과거 기록에 쓰던 UUID는 가짜 기기에 재사용하지 않는다. 토큰 발급과 설정 파일
  저장이 아직이면 [Codex 설정 가이드 1–3단계](CODEX_AGENT.md#later-owner-walkthrough--synthetic-only)만 수행한다.
  토큰은 숨김 입력으로 저장하고 화면에서는 숨긴다. 개인 Codex 홈은 지정하지 않는다.
- 아래 스풀/설정 경로는 같은 가짜 소스의 기존 것을 재사용한다. 다른 소스나 선택
  revision에 쓰던 스풀은 공유하지 않는다. GitHub 경로는 예전 가이드와 같은 이름이다.

### U1. 오프라인 대기 → 수집 → 반복/변경

Codex 에이전트를 실행하지 않은 채 **Collect device now**를 누른다. 대기 job과
오프라인/최근 연결 안내가 구분되는지 본다. 최근 실행했다면 오프라인 표시는 마지막
접촉 후120초가 지난 뒤 바뀔 수 있다. 대기가 곧 실패라는 안내여서는 안 된다.

GitHub의 **Collect now**를 누르고 저장소 루트에서 실행한다.

```bash
.venv/bin/python -m app.workers.collection_worker \
  --subscription-id GITHUB_SUBSCRIPTION_ID \
  --spool .local/phase41-synthetic-spool --synthetic --synthetic-revision 1
```

GitHub는 끝나고 Codex의 원래 job은 대기 중이어야 한다. GitHub가 이미 revision2를
확인한 데모라면 revision1로 되돌리지 말고 revision2부터 같은 상태로 반복한다.
아직 revision1 단계라면 **Collect now** 후 동일 명령을 반복하고, 한 번 더 요청해
`--synthetic-revision 2`로 실행한다. 이후 revision2를 반복한다.
기대 결과는 미변경 반복에서 Entry/버전이 늘지 않고, revision2의 새 커밋/문서가
과거 자료와 함께 보존되는 것이다. 이미 완료된 변경을 다시 새 결과로 요구하지 않는다.

이제 대기 중인 Codex job을 처리한다.

```bash
.venv/bin/python -m app.collectors.codex_agent run \
  --config .local/codex-agent-demo.json \
  --spool .local/codex-agent-demo-spool \
  --synthetic --synthetic-revision 1 --max-cycles 1
```

**Collect device now** 후 같은 revision을 반복하고, 다음 요청에는 revision2로 실행한다.
이미 revision2를 확인한 데모는 revision2만 반복한다. 한 스레드의 두 가짜 turn이
유지되고 미변경 반복에 Entry/버전이 늘지 않아야 한다. 실제 파일·Codex는 읽지 않는다.
Sources의 **Collection source**로 배치를 바꾸어 보고,
<http://localhost:5173/repositories/github?scope=repo:123> 및
<http://localhost:5173/sessions/codex>에서 해당 가짜 기록을 연다.
GitHub의 미변경 S3 job이 `empty`, Codex가 unchanged 영수증을 반환하는 차이는 정상이다.

### U2. 두 소스 예약·중지·취소

두 소스의 간격을60초로 설정하고 예약을 켠다. 각각 별도 터미널에서 기존 명령을
revision2로 실행하되 GitHub에는 `--poll-seconds 5 --max-cycles 30`, Codex에는
기존 `--max-cycles 1`을 `--poll-seconds 5 --max-cycles 30`으로 바꾼다.
등록/예약 버튼만으로 프로세스가 설치되거나 실행되지는 않는다.

직접 Collect now를 누르지 않아도 due time 이후 수집 결과가 보이는지 확인한다.
첫 성공 후 두 예약을 Pause하고, 워커가 실행 중인 동안 이전 due time을 지나도
새 예약 job이 생기지 않는지 본다. 두 명령은 최대30회 tick 후 종료하며, 필요하면
Ctrl-C로 중단한다. 가짜 자료로도 CLI 종료 시각과 job 완료 여부는 별개다.

프로세스를 중단한 상태에서 두 소스에 수동 요청을 넣고 각 Cancel을 누른다.
취소 상태가 보이며, 재시작만으로 취소 job이 살아나지 않아야 한다.
예약이 일시 중지되어도 별도로 넣은 수동 요청이 대기할 수 있음도 확인한다.
각 가짜 소스의 **Allow collection**을 끄면 수집 버튼이 비활성화되는지 본다.
다시 켜더라도 취소 작업·예약·AI 권한이 저절로 활성화되어서는 안 된다.

### U3. 삭제 보호·연결 해제·상태 이해

가짜 GitHub/Codex 기록을 각각 하나 골라 Entry 상세의 **Record actions → Delete**로
삭제한다. 해당 소스를 다시 Collect now/revision2로 실행해 삭제한 기록이 되살아나지
않는지 확인한다. GitHub는 이미 커버한 graph라면 empty일 수 있다. Codex의 삭제
차단은 partial/blocked로 나타날 수 있으므로 **collection batches**의 사유를 본다.
Sources의 **Blocked from reimport**를 보고, 이 확인을 끝내기 위해 reimport를 허용할
필요는 없다. 삭제는 가짜 기록에만 수행한다.

두 예약을 중지한 채 Codex에 새 수동 요청을 넣고 **Disconnect device**를 누른다.
그 job이 취소되고 예약/토큰이 중단되며, GitHub 카드와 보관 기록은 남아 있어야 한다.
나중에 다시 연결할 때의 토큰 교체 절차만 [참고](CODEX_AGENT.md)하면 된다.
만료·회전·전송 유실의 모든 조합을 직접 재현할 필요는 없다.

각 카드의 마지막 확인/성공, 예약/대기/부분 완료와 다음 행동이 이해되는지 본다.
**AI indexing status**는 별도 조회이며, 비어 있다고 모든 기록이 미인덱싱이라는
뜻이 아니다. 이 화면 확인을 위해 embedding이나 AI 답변을 켤 필요는 없다.
실패/임대 만료가 실제로 없는 환경에서는 그 상태를 억지로 만들지 않는다.
끝나면 가짜 소스의 예약을 중지하고 직접 실행한 프로세스를 종료한다.

## B. 선택한 실제 소스 확인 — 별도 범위를 정한 뒤

실제 자료 수집은 아직 승인/실행하지 않았다. 진행할 때 저장소/기기 UUID,
선택 branch·문서·discussion·CWD/thread, 제외 범위, 실행 횟수/시간과 업로드 대상을
먼저 정한다. 토큰·원문은 Git/채팅/확인표에 넣지 않는다. 기존 AI 권한을 넓히지 않는다.

정해진 범위에서 원하는 실제 커밋/문서와 Codex turn을 찾아 원본과 대조하고,
한 번 더 수집해 중복·선택 밖 자료 유입이 없는지 본다. 빈 저장소/discussion이나
기록되지 않은 결과·날짜·과거 편집은 없는 그대로 한계로 남긴다. 전체 이력의 완전성을
작은 표본 확인만으로 선언하지 않는다. 최초 사용자 확인과 반복 결과를 기록한다.

## C. 실제 운영 확인 — 실행 환경이 있을 때

승인된 범위에서 에이전트를 종료해 둔 동안 수동 요청이 대기하는지, 같은 설정/스풀로
재시작하면 복구되는지 관찰한다. 다음으로 실제 Mac 잠자기·깨우기를 한 번 관찰한다.
자던 동안의 요청/연결 표시, 깨어난 뒤 같은 기기 범위에서의 복구와 중복 방지를 본다.

**Mac이 잠든 동안에도 GitHub가 진행한다**는 A7 확인에는 GitHub 워커/API/DB가
그 Mac 밖에서 실행되는 환경이 필요하다. 모두 같은 Mac에서 실행 중이면 이 부분은
보류다. 에이전트만 종료한 합성 테스트를 실제 잠자기 통과로 기록하지 않는다.
이 확인만을 위해 AWS를 새로 만들거나 자동 시작 서비스를 설치하지 않는다.
실제 IAM/네트워크/DLQ·배포·성능·백업 수용은 별도 운영 범위다.
